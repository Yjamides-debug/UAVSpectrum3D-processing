# UAVSpectrum3D processing pipeline

This repository contains the processing, validation, and reference-reuse code
for **UAVSpectrum3D**, a UAV-borne received-power spectrum dataset covering
860--930 MHz at 201 centre-frequency sampling points.

Dataset record: [UAVSpectrum3D on Zenodo](https://doi.org/10.5281/zenodo.21983541)

The dataset and this code repository are separate research objects. The Zenodo
dataset is licensed under CC BY 4.0; the source code in this repository is
licensed under the MIT License.

Software author and maintainer: **Qianqian Yu**.

## What the pipeline does

The formal v0.4.0 workflow is divided into nine independently runnable stages:

1. audit source files and record completeness;
2. standardize fields, units, coordinates, spectra, and quality states;
3. audit height, power, and auxiliary sensor fields;
4. generate experimental horizontal-coordinate reconstructions;
5. build 10 m and 20 m matrix and four-dimensional tensor products;
6. create deterministic frequency-completion reference tasks;
7. evaluate aggregation-grid and quality-policy sensitivity;
8. evaluate downstream sensitivity to coordinate representation; and
9. validate stage contracts and assemble a release package.

Raw dBm measurements are retained without replacement. Exported GPS
coordinates remain the primary measured coordinates. The RTS and
quantization-aware coordinates are model-derived reference-reuse outputs and
are not treated as navigation ground truth. The 10 m and 20 m values are
aggregation-grid scales, not positioning resolutions.

## Repository layout

```text
UAVSpectrum3D-processing/
|-- run_pipeline.py
|-- uavspectrum3d_pipeline/   # reusable parsing and transformation functions
|-- stages/                   # the nine formal processing stages
|-- experiments/              # supplementary sensitivity and audit scripts
|-- figure_generation/        # figures generated during formal validation
|-- tests/                    # component contract tests
|-- requirements.txt
|-- pyproject.toml
|-- CITATION.cff
`-- LICENSE
```

Raw data, intermediate outputs, and generated release files are intentionally
not tracked by Git. They are written under `data/`, `work/`, and `build/`, all
of which are excluded through `.gitignore`.

## Installation

Python 3.13.5 was used for the validated release build. Create a clean virtual
environment and install the pinned dependencies:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Linux or macOS:

```bash
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## Input data

Download and extract the Zenodo dataset. Either place it at
`data/UAVSpectrum3D/` so that the raw CSV files are located at
`data/UAVSpectrum3D/raw/original_csv/`, or supply the CSV directory explicitly
with `--input-dir`.

The repository does not redistribute the raw measurement files.

## Run the formal pipeline

With the default directory layout:

```bash
python run_pipeline.py
```

With explicit paths:

```bash
python run_pipeline.py \
  --input-dir /path/to/UAVSpectrum3D/raw/original_csv \
  --work-dir /path/to/work/v0.4.0 \
  --release-dir /path/to/build/UAVSpectrum3D
```

PowerShell uses backticks instead of backslashes for line continuation, or the
command may be entered on one line.

To resume from a selected stage:

```bash
python run_pipeline.py --start-stage 4 --stop-stage 9
```

Stages 2--9 depend on products generated by preceding stages in the same work
directory. Individual stages can also be called directly with `--help`.

## Supplementary analyses

The `experiments/` directory contains analyses used to delimit interpretation
of the processed products:

- `batch_power_sensitivity.py` performs the fixed-height leave-one-batch-out
  power audit, including the 9 m batch sensitivity analysis;
- `trajectory_motion_audit.py` summarizes agreement between exported GPS
  displacement and motion fields; and
- `low_altitude_height_reference_audit.py` examines the GPS elevation field as
  an auxiliary reference without converting it into calibrated UAV altitude.

For example:

```bash
python experiments/batch_power_sensitivity.py \
  --release data/UAVSpectrum3D \
  --output work/batch_power_sensitivity
```

## Tests

Run the component contract tests from the repository root:

```bash
python -m unittest discover -s tests -v
```

The formal Stage 09 checks record counts, frequency-axis consistency, matrix
and tensor equivalence, split integrity, and output checksums before assembling
the release directory.

## Reproducibility notes

- The common frequency axis contains 201 centre frequencies from 860.0 to
  930.0 MHz with a 350 kHz centre-frequency step. Acquisition RBW is 1 MHz.
- Power-quality states are flags; they do not replace or delete measured dBm
  values.
- Core coordinate-indexed products contain fixed-height records with usable
  horizontal coordinates. Dynamic circular and descending flights remain
  separately indexed.
- Unobserved matrix and tensor values remain `NaN` and are accompanied by
  observation and quality masks. No spatial interpolation is applied when the
  formal products are generated.
